# Shared data and evaluation protocol

- **Inputs.** Load `eventflow_train.csv` with `eventflow.data.load_events` to get rows ordered by machine and event index. `sequence_id` is a grouping key.
- **Predictive manifests (v2).** `results/prefix_manifest.csv` has `sequence_id,prefix_len,split`. There are eight validation cutoffs per machine. Use sequence_id and prefix_len together as the prediction key. For integer `L = prefix_len`, observed rows are `seq.iloc[:L]` and the next-event label is `seq.iloc[L].event_type`. Use the training systems only to fit anything learned from data. For example, fit a normalizer or a missing-value fill on those systems and apply it unchanged to validation.
- **Model comparison.** Evaluate every model on all 10,400 validation rows from the v2 manifest. The classical_inner_split.csv file defines fitting, early-stopping, and calibration partitions for the classical model. Score the mean loss over cutoffs and resample complete machines for paired confidence intervals. Keep the order in `results/classes.json` when computing probabilities. Call `eventflow.data.multiclass_loss(y, probabilities, classes)`. Deep models can add training cutoffs on fitting systems if the team documents the difference and the comparison still uses the common validation cutoffs.
- **Generation.** `results/rollout_manifest.csv` contains only validation systems and specifies `prefix_len` and a 20-event horizon. The real continuation is `seq.iloc[L:L+20]`. Train the generator on fitting systems, use multiple sampled continuations per real prefix, and compute marginal, ordering and diversity diagnostics on matched real examples. Report both the number of prefixes and the number of generated continuations.
- **Final predictions.** Export one CSV row per test `sequence_id`. Use columns named `p__EVENT_NAME` for every class. `score` joins by ID, checks the probabilities and evaluates log loss. Reserve the provided labels for the final team selection.
- **Experiment records.** Record run ID, model, feature groups, hyperparameters, split seed, number of cutoffs, owner and validation loss. Preserve distinct names for independent runs. The validation estimate used for tuning and choosing feature groups is not an independent estimate of final performance.

To compare two sets of validation predictions, join them on both keys, order each probability matrix using classes.json, and compute one loss per cutoff with eventflow.analysis.example_loss. Pass the aligned machine IDs and the per-cutoff loss difference to MachineBootstrap.interval. For a difference computed as variant minus reference, a positive value means the variant has higher loss.
